# 実験使用機材：心拍連動型対話システム（HCS ver.4.0）

## 1. システム概要

### 1.1 開発背景と目的

本研究では、対話者の自律神経系活動をリアルタイムで計測し、その生理状態に応じて音声合成の韻律特性を動的に調整する心拍連動型対話システム（Heart-rate Coupled conversation System; HCS）ver.4.0を開発・使用した。本システムは、ウェアラブル心拍センサから取得した心拍データに基づき、閉ループ制御により音声韻律パラメータを自動調整することで、対話を通じた心拍数の誘導を試みるバイオフィードバックシステムである。

従来の心拍バイオフィードバック研究では、視覚的フィードバック（画面上のグラフ表示）や呼吸誘導が主流であったが、本システムは音声対話という自然なインタラクションを通じて、被験者が意識的な努力を行うことなく（mindless intervention）生理状態の変容を促すことを特徴とする。

## 2. ハードウェア構成

### 2.1 心拍計測デバイス

#### 2.1.1 Polar Verity Sense

心拍フィードバック制御の入力信号として、Polar Electro社製の光学式心拍センサPolar Verity Senseを使用した。本デバイスは腕装着型のフォトプレチスモグラフィ（PPG）センサであり、緑色LED光源と光検出器により脈波を計測し、心拍数を算出する。

| 項目 | 仕様 |
|------|------|
| 計測方式 | 光学式（PPG） |
| 装着部位 | 前腕部 |
| 心拍数出力 | 約1Hz（拍動毎） |
| 通信方式 | Bluetooth Low Energy (BLE) |
| 心拍数特性UUID | `00002a37-0000-1000-8000-00805f9b34fb` |

BLE Heart Rate Measurement特性のデータ形式は以下の通りである：

```
Byte 0: フラグバイト
  bit 0: 心拍値フォーマット（0=UINT8, 1=UINT16）
  bit 1-2: センサ接触状態
  bit 3: エネルギー消費フィールドの有無
  bit 4: RR間隔フィールドの有無

Byte 1(-2): 心拍数値（BPM）
  UINT8の場合: 1バイト（0-255 BPM）
  UINT16の場合: 2バイト（リトルエンディアン）
```

#### 2.1.2 Polar H10

心拍変動（HRV）解析用の心電図（ECG）データ取得には、Polar Electro社製の胸部装着型心電計Polar H10を使用した。本デバイスは医療グレードに準ずる精度で単一誘導心電図を計測可能である。

| 項目 | 仕様 |
|------|------|
| 計測方式 | 電極式（1誘導ECG） |
| 装着部位 | 胸部（剣状突起レベル） |
| サンプリング周波数 | 130 Hz |
| 分解能 | 14 bit |
| 電圧単位 | μV（マイクロボルト） |
| 通信方式 | Bluetooth Low Energy (BLE) |
| PMDサービスUUID | `FB005C80-02E7-F387-1CAD-8ACD2D8DF0C8` |
| PMD制御特性UUID | `FB005C81-02E7-F387-1CAD-8ACD2D8DF0C8` |
| PMDデータ特性UUID | `FB005C82-02E7-F387-1CAD-8ACD2D8DF0C8` |

ECGストリーミング開始コマンドは以下のバイト列で構成される：

```
0x02: リクエストタイプ（開始）
0x00: 計測タイプ（ECG）
0x00, 0x01, 0x82, 0x00: サンプリングレート設定（130Hz）
0x01, 0x01, 0x0E, 0x00: 分解能設定（14bit）
```

ECGデータパケットの形式：

```
Byte 0: データタイプ（0x00 = ECG）
Byte 1-8: デバイスタイムスタンプ（ナノ秒、リトルエンディアン）
Byte 10以降: ECGサンプル（3バイト/サンプル、符号付きリトルエンディアン）
```

## 3. ソフトウェア構成

### 3.1 音声認識モジュール

音声認識にはOpenAI Whisperモデルのfaster-whisper実装を使用した。faster-whisperはCTranslate2による最適化実装であり、オリジナルのWhisperと比較して2-4倍高速な推論が可能である（Bain et al., 2023）。

| 環境 | モデルサイズ | 計算精度 | 備考 |
|------|-------------|---------|------|
| CUDA (NVIDIA GPU) | small (244M パラメータ) | float16 | GPU高速推論 |
| CPU / MPS | base (74M パラメータ) | int8 (量子化) | メモリ効率優先 |

音声認識パラメータ：
- ビームサーチ幅：5
- 言語：日本語（自動検出）

### 3.2 大規模言語モデル（LLM）

対話応答生成には、ローカルで動作する量子化LLMを使用した。推論サーバにはllama.cppを採用し、GGUFフォーマットの量子化モデルをロードする構成とした。

| パラメータ | 設定値 | 説明 |
|-----------|--------|------|
| コンテキストサイズ | 4,096トークン | 会話履歴の保持量 |
| 最大生成トークン数 | 200トークン | 1応答あたりの上限 |
| 温度（Temperature） | 0.7 | 生成の多様性制御 |
| タイムアウト | 30秒 | 応答待機時間上限 |
| GPUレイヤー数 | -1（全層）または0（CPU） | 自動検出による設定 |

代替として、OpenAI API（gpt-4o-mini）への接続も可能であり、`USE_LOCAL_LLM`フラグにより切り替えられる。

### 3.3 音声合成モジュール

音声合成にはVOICEVOX Engine（ver. 0.14以降）を使用した。VOICEVOXは深層学習に基づく日本語テキスト音声合成（TTS）エンジンであり、韻律パラメータのリアルタイム制御が可能である。

制御可能な韻律パラメータ：

| パラメータ | 説明 | 制御範囲 | デフォルト値 | 単位 |
|-----------|------|---------|-------------|------|
| intonationScale | 抑揚（イントネーション）の強度 | 0.0 - 2.0 | 1.0 | 倍率 |
| pitchScale | 基本周波数のシフト量 | -0.15 - 0.15 | 0.0 | オクターブ |
| speedScale | 発話速度 | 0.5 - 2.0 | 1.0 | 倍率 |
| volumeScale | 音量 | 0.0 - 2.0 | 1.0 | 倍率 |
| prePhonemeLength | 発話前休止時間 | 0.0 - 2.0 | 0.1 | 秒 |
| postPhonemeLength | 発話後休止時間 | 0.0 - 2.0 | 0.1 | 秒 |

intonationScale（抑揚）パラメータは、音声のピッチ変動幅を制御し、値が大きいほど抑揚が強調された表現豊かな音声となる。本研究では主にこのパラメータを心拍フィードバック制御の操作量として使用した。

### 4.2 心拍数取得タイミング

心拍フィードバック制御において、心拍数は以下の2時点で取得・記録される：

1. **発話開始時（HR at Recording Start）**
   - 取得方法：発話開始時刻を中心とした前後2秒間（計4秒間）のスライディングウィンドウから心拍数サンプルを抽出し、中央値を算出
   - 目的：発話時の生理状態の記録、事後解析用

2. **音声再生終了時（HR after TTS）**
   - 取得方法：音声再生終了時点の瞬時心拍数
   - 目的：次回発話の韻律決定に使用（直接調整モード）、制御効果の評価

スライディングウィンドウによる中央値算出は、心拍計測のアーチファクト（体動ノイズ等）の影響を軽減するために採用した。

```python
def get_buffered_hr(self, target_time, window_seconds=2.0):
    """
    指定時刻を中心とした時間窓から心拍数の中央値を算出

    Args:
        target_time: 中心時刻
        window_seconds: 前後の時間幅（秒）

    Returns:
        int: 心拍数の中央値（BPM）、データ不足時はNone
    """
    window_start = target_time - timedelta(seconds=window_seconds)
    window_end = target_time + timedelta(seconds=window_seconds)

    hr_values = [
        entry['hr'] for entry in self.hr_buffer
        if window_start <= entry['timestamp'] <= window_end
    ]

    if len(hr_values) >= MIN_SAMPLES_FOR_MEDIAN:
        return int(statistics.median(hr_values))
    return None
```

## 5. 心拍フィードバック制御機構

### 5.1 制御モードの概要

本システムは4種類の制御モードを実装しており、研究目的に応じて選択可能である。

| モード | 名称 | 特徴 | 用途 |
|--------|------|------|------|
| Fixed | 固定値モード | 韻律パラメータを手動設定値に固定 | 対照条件、ベースライン |
| Sin | 正弦波モード | 心拍非依存で韻律を周期的に変化 | 韻律変化の効果検証 |
| HRF | 直接調整モード | 心拍差分に感度係数を乗じて韻律を算出 | 単純なフィードバック |
| HRF2 | 制御則モード | PID/適応/ゲインスケジューリング/ロバスト制御 | 目標心拍追従制御 |

### 5.2 直接調整モード（HRF）の計算式

直接調整モードでは、基準心拍数からの偏差に感度係数を乗じて韻律パラメータを算出する。

**基本計算式：**

$$
p = p_0 + k \cdot (HR_{after} - HR_{ref})
$$

ここで、
- $p$：適用される韻律パラメータ値
- $p_0$：基本値（デフォルト値）
- $k$：感度係数
- $HR_{after}$：前回音声再生後の心拍数（BPM）
- $HR_{ref}$：基準心拍数（BPM）

**各パラメータの設定値：**

| パラメータ | 基本値 $p_0$ | 感度係数 $k$ | 制御範囲 |
|-----------|-------------|-------------|---------|
| intonation（抑揚） | 1.0 | 0.1 | [0.0, 2.0] |
| pitch（ピッチ） | 0.0 | 0.002 | [-0.15, 0.15] |
| speed（速度） | 1.0 | 0.003 | [0.5, 2.0] |
| energy（音量） | 1.0 | 0.005 | [0.0, 2.0] |
| pause_duration（休止） | 1.0 | 0.003 | [0.0, 2.0] |

**計算例（抑揚の場合）：**

基準心拍数 $HR_{ref} = 70$ BPM、前回再生後心拍数 $HR_{after} = 85$ BPMの場合：

$$
\text{intonation} = 1.0 + 0.1 \times (85 - 70) = 1.0 + 1.5 = 2.5
$$

制御範囲[0.0, 2.0]に制限されるため、実際に適用される値は2.0となる。

この制御則の意味合いとして、心拍数が上昇（興奮状態）した場合は抑揚を強め、心拍数が低下（鎮静状態）した場合は抑揚を弱めることで、生理状態と音声特性の同期を図る。

### 5.3 正弦波モード（Sin）

正弦波モードは心拍数に依存せず、韻律パラメータを周期的に変化させるモードである。制御効果の検証において、韻律変化自体の影響を評価するための対照条件として使用可能である。

**シーケンス生成アルゴリズム：**

```python
def _generate_sinusoidal_sequence():
    sequence = []
    # 上昇相：1.0 → 2.0（0.1刻み、11ステップ）
    sequence.extend([round(1.0 + i * 0.1, 1) for i in range(11)])
    # 下降相：1.9 → 0.0（0.1刻み、20ステップ）
    sequence.extend([round(1.9 - i * 0.1, 1) for i in range(20)])
    # 回復相：0.1 → 0.9（0.1刻み、9ステップ）
    sequence.extend([round(0.1 + i * 0.1, 1) for i in range(9)])
    return sequence  # 計40ステップで1周期
```

各音声合成時に1ステップずつ進行し、約40発話で1周期を完了する三角波形状のパターンを生成する。

### 5.4 HRF2制御モード

HRF2は、目標心拍数への追従を目的とした閉ループ制御モードであり、以下の4種類の制御則を実装している。

#### 5.4.1 PID制御（ControlMode.PID）

古典的な比例・積分・微分制御に基づく方式である。

**制御則：**

$$
u(t) = 1.0 + K_p e(t) + K_i \int_0^t e(\tau) d\tau + K_d \frac{de(t)}{dt}
$$

ここで、
- $u(t)$：抑揚パラメータ（操作量）
- $e(t) = HR_{target} - HR_{current}$：偏差
- $K_p, K_i, K_d$：比例、積分、微分ゲイン

**実装上の工夫：**

1. **デッドバンド処理**：$|e| < 3.0$ BPMの場合、$e = 0$として過剰な制御動作を抑制

2. **アンチワインドアップ**：積分項を$[-20.0, 20.0]$に制限し、積分器の飽和を防止

3. **離散化**：後退差分法による微分項の近似
   $$
   \frac{de}{dt} \approx \frac{e[k] - e[k-1]}{\Delta t}
   $$

**デフォルトパラメータ：**

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| $K_p$ | 0.02 | 比例ゲイン |
| $K_i$ | 0.005 | 積分ゲイン |
| $K_d$ | 0.01 | 微分ゲイン |
| デッドバンド | 3.0 BPM | 不感帯幅 |
| 目標心拍数 | 70.0 BPM | 制御目標 |

#### 5.4.2 適応制御（ControlMode.ADAPTIVE）

モデル規範型適応制御（Model Reference Adaptive Control; MRAC）に基づく方式であり、MIT則によりゲインを動的に調整する。

**参照モデル：**

一次遅れ系を参照モデルとして採用した：

$$
\tau \frac{d r(t)}{dt} + r(t) = HR_{target}
$$

離散化形式：

$$
r[k+1] = r[k] + \frac{\Delta t}{\tau} (HR_{target} - r[k])
$$

ここで、$\tau = 30$秒（心拍数の生理的応答遅れを考慮）。

**適応則（MIT則）：**

追従誤差 $e_{track} = r(t) - HR_{current}$ を最小化するよう、適応パラメータ$\theta$を更新する：

$$
\theta[k+1] = \lambda \cdot \theta[k] + \gamma \cdot \frac{e_{track} \cdot u_{sens}}{1 + \alpha \cdot u_{sens}^2}
$$

ここで、
- $\lambda = 0.995$：忘却係数（パラメータドリフト防止）
- $\gamma = 0.001$：適応速度
- $\alpha = 0.01$：正規化ゲイン
- $u_{sens}$：感度（前回出力値）

**制御出力：**

$$
u(t) = 1.0 + \theta \cdot e_{control}
$$

ここで、$e_{control} = HR_{target} - HR_{current}$（デッドゾーン$\pm 2.0$ BPM処理後）。

適応パラメータ$\theta$は$[0.005, 0.1]$の範囲に制限され、制御系の安定性を確保する。

#### 5.4.3 ゲインスケジューリング制御（ControlMode.GAIN_SCHEDULED）

偏差の大きさに応じてPIDゲインを動的に切り替える方式である。大きな偏差では積極的に追従し、小さな偏差では微調整に留めることで、収束速度と安定性のバランスを実現する。

**ゲイン領域の定義：**

| 領域 | 条件 | $K_p$ | $K_i$ | $K_d$ | ゲイン種別 |
|------|------|-------|-------|-------|-----------|
| 大偏差（High） | $|e| \geq 15.0$ BPM | 0.04 | 0.008 | 0.015 | PID |
| 中偏差（Medium） | $7.0 \leq |e| < 15.0$ BPM | 0.02 | 0.005 | 0.01 | PI |
| 小偏差（Low） | $|e| < 7.0$ BPM | 0.01 | 0.002 | 0.005 | P |

**ゲイン平滑化：**

急激なゲイン切り替えによるチャタリングを防止するため、指数移動平均によるゲイン平滑化を実装した：

$$
K[k+1] = K[k] + \alpha_s (K_{target} - K[k])
$$

ここで、$\alpha_s = 0.3$（平滑化係数）。

#### 5.4.4 ロバスト制御（ControlMode.ROBUST）

モデル誤差抑制補償器（Model Error Compensator; MEC）を用いた頑健制御方式である。名目モデルと実際の人体応答の差異を補償することで、個人差や日内変動に対する頑健性を確保する。

**制御構造：**

```
         error ────> [PI制御器 K₀] ──> u₀ ─┐
                                            │
                                            ├──(+)──> u ──> [人体 G] ──> y
                                            │
                              u_mec ◄── [MEC: Cε] ◄── ε = y - ŷ
                                                        ▲
                                              [名目モデル Ĝ] ──> ŷ
```

**名目モデル $\hat{G}$：**

一次遅れ系にむだ時間を加えたモデル：

$$
\hat{G}(s) = \frac{K}{1 + \tau s} e^{-Ls}
$$

離散化実装：

$$
\hat{y}[k+1] = \hat{y}[k] + \frac{\Delta t}{\tau + \Delta t} (K \cdot (u_{delayed} - 1.0) + HR_{baseline} - \hat{y}[k])
$$

**パラメータ：**
- $K = 5.0$：定常ゲイン（抑揚1.0の変化がHRに与える影響）
- $\tau = 30.0$秒：時定数
- $L = 5.0$秒：むだ時間

**MEC補償器 $C_\varepsilon$：**

モデル誤差$\varepsilon = y - \hat{y}$を低域通過フィルタを通して補償入力に変換：

$$
C_\varepsilon(s) = \frac{k_{mec}}{1 + s/\omega_c}
$$

離散化：

$$
\varepsilon_{filtered}[k+1] = \varepsilon_{filtered}[k] + \alpha_{mec} (k_{mec} \cdot \varepsilon - \varepsilon_{filtered}[k])
$$

$$
u_{mec} = -\varepsilon_{filtered}
$$

**パラメータ：**
- $k_{mec} = 0.3$：MEC利得
- $\omega_c = 0.05$ rad/s：カットオフ周波数

**スルーレート制限：**

急激な操作量変化を防止するため、1ステップあたりの変化量を$\pm 0.15$に制限：

$$
u[k] = \begin{cases}
u[k-1] + 0.15 & \text{if } u_{raw} - u[k-1] > 0.15 \\
u[k-1] - 0.15 & \text{if } u_{raw} - u[k-1] < -0.15 \\
u_{raw} & \text{otherwise}
\end{cases}
$$

**計測ノイズフィルタ：**

心拍数計測値に一次ローパスフィルタを適用：

$$
HR_{filtered}[k+1] = HR_{filtered}[k] + \frac{\Delta t}{\tau_f + \Delta t} (HR_{raw} - HR_{filtered}[k])
$$

ここで、$\tau_f = 2.0$秒。

## 6. 目標心拍数の設定方法

### 6.1 基準心拍数の測定

実験開始前に、被験者の安静時心拍数をベースライン測定により取得した。測定プロトコルは以下の通りである：

1. 被験者に椅子座位で安静を維持するよう指示
2. 心拍センサ装着後、30秒間（設定により変更可能）の心拍数を連続記録
3. 取得したサンプルから中央値を算出し、基準心拍数（$HR_{ref}$）として設定

中央値の採用理由は、体動等によるアーチファクトの影響を軽減するためである。

```python
def stop_baseline_measurement(self):
    """ベースライン測定を終了し、中央値を基準心拍数として設定"""
    if len(self.baseline_samples) >= MIN_SAMPLES_FOR_MEDIAN:
        median_hr = int(statistics.median(self.baseline_samples))
        self.set_reference_hr(median_hr)
        return median_hr
    return None
```

### 6.2 目標心拍数の設定根拠

心拍フィードバック制御における目標心拍数は、以下の考慮事項に基づき設定した。

#### 6.2.1 相対目標設定の採用

先行研究（参考文献の調査に基づく）では、認知・無意識下の心拍制御において、固定値の目標心拍数よりも基準心拍数からの相対変化（パーセンテージまたは差分）による目標設定が推奨されている。これは以下の理由による：

1. **個人差の吸収**：安静時心拍数は個人により60-90 BPMと大きく異なるため、絶対値での目標設定は不適切
2. **生理的妥当性**：相対変化は自律神経活動の変化量としてより意味のある指標
3. **制御の安定性**：固定目標値への強い追従は、個体差により発振や不安定化を招く可能性

#### 6.2.2 目標値の設定例

本研究では、会話による覚醒水準の適度な向上を目的とし、基準心拍数の+10%を目標値として設定した：

$$
HR_{target} = HR_{ref} \times 1.10
$$

例：$HR_{ref} = 70$ BPMの場合、$HR_{target} = 77$ BPM

この設定は、ヤーキーズ・ドットソンの法則に基づく最適覚醒理論を参考としているが、音声韻律による心拍誘導に関する直接的なエビデンスは限定的であり、**探索的な設定**として位置づけられる。

#### 6.2.3 安全制約

目標心拍数は以下の範囲に制限される：

$$
40 \leq HR_{target} \leq 180 \text{ (BPM)}
$$

また、デッドバンド（±2〜3 BPM）の設定により、目標値付近での過剰な制御動作を抑制している。

## 8. ECG解析機能

### 8.1 QRS検出アルゴリズム

Polar H10から取得したECGデータからR波を検出し、RR間隔（RRI）を算出する。検出アルゴリズムはPan-Tompkinsアルゴリズムを参考に実装した。

**処理手順：**

1. **バンドパスフィルタリング**
   - 通過帯域：0.5 Hz - 50 Hz
   - 目的：ベースラインワンダーと高周波ノイズの除去

2. **微分処理**
   $$
   y[n] = x[n] - x[n-1]
   $$

3. **二乗処理**
   $$
   z[n] = y[n]^2
   $$

4. **移動積分**
   - 窓幅：150 ms（130Hz × 0.15 = 約20サンプル）
   $$
   w[n] = \frac{1}{N} \sum_{i=0}^{N-1} z[n-i]
   $$

5. **ピーク検出**
   - 閾値：積分信号平均値の40%
   - 最小ピーク間隔：300 ms（生理学的に妥当なRR間隔下限）

### 8.2 心拍変動（HRV）指標

検出されたRR間隔から以下のHRV指標を算出可能である：

**時間領域指標：**

| 指標 | 定義 | 意味 |
|------|------|------|
| SDNN | RR間隔の標準偏差 | 全体的な心拍変動性 |
| RMSSD | 隣接RR間隔差の二乗平均平方根 | 副交感神経活動 |
| pNN50 | 50ms以上異なる隣接RR間隔の割合 | 副交感神経活動 |

**周波数領域指標：**

| 指標 | 周波数帯域 | 意味 |
|------|-----------|------|
| LF | 0.04 - 0.15 Hz | 交感・副交感神経活動 |
| HF | 0.15 - 0.40 Hz | 副交感神経（迷走神経）活動 |
| LF/HF比 | - | 自律神経バランス |

周波数解析にはWelch法によるパワースペクトル密度推定を使用した。

## 9. スレッド安全性とエラーハンドリング

### 9.1 排他制御機構

本システムは複数のスレッド（BLE通信、音声処理、GUI更新、ログ記録）が並行動作するため、共有リソースへのアクセスには適切な排他制御を実装した。

| 共有リソース | ロック機構 | 用途 |
|-------------|-----------|------|
| 心拍数データ（current_hr, hr_buffer） | `threading.Lock` (hr_lock) | BLE受信と読み取りの排他 |
| TTS処理状態 | `threading.Lock` (tts_lock) | 同時発話の防止 |
| ログキュー | `queue.Queue` | スレッドセーフなログ書き込み |

```python
class HeartRateMonitor:
    def __init__(self):
        self.hr_lock = threading.Lock()

    def get_current_hr(self) -> int:
        with self.hr_lock:
            return self.current_hr

    def hr_notification_handler(self, sender, data):
        with self.hr_lock:
            self.current_hr = hr_value
            self.hr_buffer.append({'timestamp': now, 'hr': hr_value})
```

### 9.2 BLE接続エラー処理

Linux環境（BlueZ）特有の「InProgress」エラーに対応するため、以下の対策を実装した：

1. **順次接続**：複数デバイス（Verity Sense, H10）を同時ではなく順次接続
2. **bluetoothctlによる強制切断**：既存接続のクリーンアップ
3. **リトライ機構**：最大3回の接続試行

```python
async def _bluez_disconnect_device(self, address: str) -> None:
    """Linux BlueZ: bluetoothctlでデバイスを強制切断"""
    subprocess.run(["bluetoothctl", "disconnect", address], ...)
    await asyncio.sleep(1.0)
    subprocess.run(["bluetoothctl", "remove", address], ...)
```

## 10. システムの特徴と限界

### 10.1 特徴

1. **リアルタイム閉ループ制御**：心拍計測から韻律調整までを低遅延（数秒オーダー）で実行
2. **複数制御アルゴリズム**：研究目的に応じてPID、適応制御、ロバスト制御等を選択可能
3. **非侵襲的介入**：会話という自然なインタラクションを通じた生理状態への働きかけ
4. **包括的データ記録**：心拍、ECG、会話内容、制御パラメータを時系列で記録
5. **クロスプラットフォーム**：macOS、Linuxで動作

### 10.2 限界

1. **心拍応答の遅延**：音声韻律の変化が心拍数に反映されるまでに数十秒の遅延が存在し、閉ループ制御の帯域幅を制限する

2. **個人差**：心拍数の韻律刺激に対する感受性には個人差があり、一律の制御パラメータでは最適な応答が得られない可能性がある

3. **外乱の影響**：会話内容、感情喚起、環境温度、姿勢変化等の外乱が心拍数に影響を与え、制御効果の評価を困難にする

4. **エビデンスの限界**：音声韻律による心拍誘導効果、および最適な目標心拍数設定に関する先行研究は限定的であり、本システムの設計は探索的な性質を持つ

5. **生態学的妥当性**：実験室環境での対話は日常会話と異なり、得られた知見の一般化には注意が必要である
