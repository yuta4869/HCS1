# 実験使用機材：心拍連動型対話システム（HCS ver.4.0）

## 1. システム概要

### 1.1 開発背景と目的

本研究では、対話者の自律神経系活動をリアルタイムで計測し、その生理状態に応じて音声合成の韻律特性を動的に調整する心拍連動型対話システム（Heart-rate Coupled conversation System; HCS）ver.4.0を開発・使用した。本システムは、ウェアラブル心拍センサから取得した心拍データに基づき、閉ループ制御により音声韻律パラメータを自動調整することで、対話を通じた心拍数の誘導を試みるバイオフィードバックシステムである。

### 1.2 理論的背景

#### 1.2.1 心拍バイオフィードバックの概念

バイオフィードバックとは、通常は意識されない生理的プロセスを計測・可視化し、その情報を被験者にフィードバックすることで、生理状態の自己調整を促す技術である（Schwartz & Andrasik, 2017）。心拍バイオフィードバックは、心拍数や心拍変動（Heart Rate Variability; HRV）を対象とし、自律神経系の調整を通じてストレス軽減や情動調整に効果があることが報告されている（Lehrer & Gevirtz, 2014）。

従来の心拍バイオフィードバック研究では、以下のアプローチが主流であった：

| アプローチ | 方法 | 特徴 | 限界 |
|-----------|------|------|------|
| 視覚的フィードバック | 画面上のグラフ・数値表示 | 明示的、定量的 | 意識的努力が必要 |
| 呼吸誘導 | 呼吸ペースの指示 | 効果が確立 | 注意資源を消費 |
| 聴覚フィードバック | ビープ音・音楽のテンポ | 視覚負荷なし | 単調、没入感低い |

これらの手法に共通する課題は、被験者が意識的に生理状態を制御しようとする「努力」が必要であり、認知負荷が生じる点である。

#### 1.2.2 Mindless Intervention（無意識的介入）の概念

近年、被験者が意識的な努力を行うことなく生理状態の変容を促す「mindless intervention」への関心が高まっている（Azevedo et al., 2017）。この概念は、外部刺激（視覚、聴覚、触覚等）が無意識的に自律神経系に影響を与える現象に基づく。

代表的な研究として、Offset Heart Rate Biofeedback（OHBF）がある。Costa et al.（2016）は、被験者に提示する心拍数を実際の値から意図的にずらす（例：実測の70%または130%で提示）ことで、被験者が意識せずとも心拍数が変化することを示した。この知見は、心拍の「認知」が生理状態に影響を与えることを示唆しており、本研究の音声韻律を介した無意識的介入の理論的基盤となる。

#### 1.2.3 音声韻律と生理的覚醒の関連

音声の韻律特性（prosody）—ピッチ、抑揚、速度、音量等—は、話者の情動状態を伝達するとともに、聴者の情動・生理状態にも影響を与える（Scherer, 2003）。先行研究では以下の知見が報告されている：

1. **ピッチの高さ**：高いピッチは覚醒度の上昇と関連（Banse & Scherer, 1996）
2. **抑揚の強さ**：強い抑揚は情動喚起力が高い（Juslin & Laukka, 2003）
3. **発話速度**：速い発話は興奮・緊急性を伝達（Apple et al., 1979）
4. **音量**：大きな音量は覚醒水準を高める（Tajadura-Jiménez et al., 2010）

これらの知見に基づき、本システムでは音声韻律（特に抑揚）を操作することで、対話を通じて被験者の心拍数を誘導することを試みる。

#### 1.2.4 引き込み現象（Entrainment）

引き込み（entrainment）とは、2つの振動系が相互作用により同期する現象であり、生体リズムにおいても観察される（Clayton et al., 2005）。心拍と外部リズム刺激の引き込みに関しては、以下の研究がある：

- **触覚刺激**：振動刺激のテンポを心拍より3-5%低く設定すると、心拍数が低下する（Azevedo et al., 2017）
- **聴覚刺激**：音楽のテンポが心拍数に影響を与える（Bernardi et al., 2006）
- **呼吸**：呼吸と心拍の共鳴周波数（約0.1Hz）での呼吸誘導がHRVを最大化する（Lehrer & Gevirtz, 2014）

本システムは、音声韻律という聴覚刺激を通じた心拍への引き込み効果を利用する。

### 1.3 システムの新規性

本システムの新規性は以下の点にある：

1. **音声対話を介した無意識的介入**：従来の視覚的・呼吸誘導型バイオフィードバックと異なり、自然な会話という日常的インタラクションを通じて生理状態に働きかける

2. **閉ループ制御の実装**：心拍数をリアルタイムに計測し、制御理論に基づくアルゴリズム（PID、適応制御、ロバスト制御）により韻律パラメータを自動調整する

3. **複数制御モードの統合**：研究目的に応じて制御方式を選択可能とし、比較研究を容易にする

4. **包括的データ記録**：心拍、ECG、会話内容、制御パラメータを時系列で記録し、事後解析を可能にする

### 2.3 処理タイミングと遅延

システム全体の処理遅延は、対話の自然さと制御性能の両方に影響する。各処理段階の典型的な遅延を以下に示す：

| 処理段階 | 典型的遅延 | 変動要因 |
|---------|----------|---------|
| BLE心拍受信 | 100-500 ms | BLE接続状態 |
| 音声録音 | 1.0-5.0 s | 発話長、無音検出 |
| 音声認識 (Whisper) | 0.5-2.0 s | 発話長、GPU有無 |
| LLM応答生成 | 1.0-5.0 s | モデルサイズ、GPU有無 |
| 音声合成 (VOICEVOX) | 0.3-1.0 s | テキスト長 |
| 音声再生 | 2.0-10.0 s | 応答長 |
| **合計（1ターン）** | **5-25 s** | - |

心拍の生理的応答遅れ（数十秒）を考慮すると、上記の処理遅延は制御性能に大きな影響を与えないと考えられる。

## 3. ハードウェア構成

### 3.1 心拍計測デバイス

#### 3.1.1 Polar Verity Sense

心拍フィードバック制御の入力信号として、Polar Electro社製の光学式心拍センサPolar Verity Senseを使用した。

**測定原理（フォトプレチスモグラフィ; PPG）：**

PPGは、皮膚表面に光を照射し、血液量の変化による光吸収の変動を検出することで脈波を計測する技術である。本デバイスは緑色LED（波長約520-535nm）を光源として使用する。緑色光はヘモグロビンに対する吸収係数が高く、動脈血の拍動による吸収変化を効率的に検出できる。

脈波信号から心拍数を算出するアルゴリズムは非公開であるが、一般的にはピーク検出またはゼロ交差検出法が用いられる。出力される心拍数は、直近数拍の移動平均として平滑化されていると推定される。

**デバイス仕様：**

| 項目 | 仕様 | 備考 |
|------|------|------|
| センサ方式 | 光学式（PPG） | 緑色LED + フォトダイオード |
| 装着部位 | 前腕部（上腕部も可） | 弾性バンドで固定 |
| 心拍数出力レート | 約1 Hz | 拍動検出毎に更新 |
| 心拍数測定範囲 | 30-230 BPM | 仕様値 |
| 精度 | ±1 BPM または ±1% | 安静時、ECGとの比較 |
| 通信方式 | Bluetooth Low Energy 5.0 | Bluetooth SIG Heart Rate Profile準拠 |
| バッテリー | 充電式リチウムポリマー | 連続使用約20時間 |
| 防水性能 | 水泳対応（WR30） | - |

**BLE通信プロトコル：**

本デバイスはBluetooth SIG標準のHeart Rate Profile（HRP）を実装しており、以下の特性（Characteristic）を通じて心拍データを送信する：

| 特性名 | UUID | 説明 |
|-------|------|------|
| Heart Rate Measurement | `0x2A37` | 心拍数データ（通知） |
| Body Sensor Location | `0x2A38` | センサ装着位置（読取） |
| Heart Rate Control Point | `0x2A39` | エネルギー消費リセット（書込） |

Heart Rate Measurement特性のデータ形式（Bluetooth SIG仕様）：

```
┌─────────────────────────────────────────────────────────────────┐
│ Byte 0: Flags                                                    │
│   bit 0:   Heart Rate Value Format (0=UINT8, 1=UINT16)          │
│   bit 1-2: Sensor Contact Status                                 │
│   bit 3:   Energy Expended Status (1=present)                    │
│   bit 4:   RR-Interval (1=present)                               │
│   bit 5-7: Reserved                                              │
├─────────────────────────────────────────────────────────────────┤
│ Byte 1(-2): Heart Rate Value                                     │
│   UINT8 (0-255) または UINT16 (0-65535) リトルエンディアン       │
├─────────────────────────────────────────────────────────────────┤
│ (Optional) Energy Expended: UINT16                               │
├─────────────────────────────────────────────────────────────────┤
│ (Optional) RR-Interval: UINT16 × n (1/1024秒単位)               │
└─────────────────────────────────────────────────────────────────┘
```

本システムでは、Heart Rate Value（心拍数）のみを使用し、RR-Intervalは使用しない（HRV解析にはPolar H10のECGデータを使用）。

#### 3.1.2 Polar H10

心拍変動（HRV）解析用の心電図（ECG）データ取得には、Polar Electro社製の胸部装着型心電計Polar H10を使用した。

**測定原理：**

Polar H10は、胸部に装着した2電極（導電性ゴム）間の電位差を計測する単一誘導心電計である。電極配置はModified Lead II（改良II誘導）に相当し、心臓の電気軸に沿った信号を効率的に検出できる。

**デバイス仕様：**

| 項目 | 仕様 | 備考 |
|------|------|------|
| センサ方式 | 電極式（2電極） | 導電性ゴム電極 |
| 装着部位 | 胸部（剣状突起レベル） | 専用チェストストラップ |
| ECGサンプリング周波数 | 130 Hz | 固定 |
| ECG分解能 | 14 bit | ダイナミックレンジ拡大 |
| ECG電圧単位 | μV（マイクロボルト） | 符号付き整数 |
| 心拍数出力 | 約1 Hz | BLE HRPによる |
| 精度 | ±1 BPM | ECGベースのため高精度 |
| 通信方式 | Bluetooth Low Energy 5.0 | Polar独自PMDサービス併用 |

**Polar Measurement Data（PMD）サービス：**

ECGデータの取得には、Polar独自のPMDサービスを使用する。このサービスはBluetooth SIG標準ではなく、Polar社が独自に定義したプロファイルである。

| 特性名 | UUID | 説明 |
|-------|------|------|
| PMD Control Point | `FB005C81-...` | 計測開始/停止コマンド送信 |
| PMD Data | `FB005C82-...` | ECGデータストリーム受信 |

**ECGストリーミング開始コマンド：**

```
Byte 0: 0x02    # リクエストタイプ（開始）
Byte 1: 0x00    # 計測タイプ（ECG）
Bytes 2-5:      # サンプリングレート設定
  0x00, 0x01    #   設定タイプ: Sample Rate
  0x82, 0x00    #   値: 130 Hz (0x0082 リトルエンディアン)
Bytes 6-9:      # 分解能設定
  0x01, 0x01    #   設定タイプ: Resolution
  0x0E, 0x00    #   値: 14 bit (0x000E)
```

**ECGデータパケット形式：**

```
┌─────────────────────────────────────────────────────────────────┐
│ Byte 0: Data Type (0x00 = ECG)                                  │
├─────────────────────────────────────────────────────────────────┤
│ Bytes 1-8: Device Timestamp (ナノ秒, リトルエンディアン)         │
│   64-bit unsigned integer                                       │
├─────────────────────────────────────────────────────────────────┤
│ Byte 9: Frame Type (通常 0x00)                                  │
├─────────────────────────────────────────────────────────────────┤
│ Bytes 10-: ECG Samples (3バイト/サンプル × n)                   │
│   各サンプル: 24-bit signed integer (リトルエンディアン)         │
│   値: ECG電圧 (μV単位)                                          │
│   パケットあたり約73サンプル (130Hz × 0.56秒)                    │
└─────────────────────────────────────────────────────────────────┘
```

#### 3.1.3 PPGとECGの比較

| 項目 | PPG (Verity Sense) | ECG (H10) |
|------|-------------------|-----------|
| 測定対象 | 末梢血管の容積変化 | 心臓の電気活動 |
| 時間分解能 | 低（約1Hz出力） | 高（130Hzサンプリング） |
| 体動アーチファクト | 影響大 | 影響小 |
| HRV解析 | 限定的 | 可能（RRI算出可） |
| 装着容易性 | 高（腕装着） | 中（胸部装着） |
| 長時間装着快適性 | 高 | 中 |

本システムでは、リアルタイム心拍フィードバック制御にはPPG（Verity Sense）を使用し、詳細なHRV解析にはECG（H10）を使用する二重計測構成を採用した。

    """利用可能なGPUバックエンドを検出"""
    import torch

    if torch.cuda.is_available():

        return "cuda", -1  # 全レイヤーをGPUに

#### 4.3.3 抑揚パラメータの詳細

本研究では、主に**intonationScale（抑揚）**パラメータを心拍フィードバック制御の操作量として使用した。

抑揚パラメータは、音声のピッチ（基本周波数F0）の変動幅を制御する。値が1.0の場合は元の韻律パターンが維持され、1.0より大きい場合はピッチの高低差が拡大（より抑揚が強調）され、1.0より小さい場合はピッチ変動が縮小（より単調）される。

```
intonationScale = 0.5:  ───────────────  (単調、感情表出弱)
                              ↓
intonationScale = 1.0:  ─────/\────\/─  (標準)
                              ↓
intonationScale = 2.0:  ────/  \──/  \─ (抑揚強調、感情表出強)
```

### 5.2 心拍数取得の詳細

#### 5.2.1 取得タイミングと目的

心拍フィードバック制御において、心拍数は以下の2時点で取得・記録される：

| 取得タイミング | 変数名 | 取得方法 | 目的 |
|---------------|--------|---------|------|
| 発話開始時 | HR at Recording Start | 前後2秒の中央値 | 発話時生理状態の記録 |
| 音声再生終了時 | HR after TTS | 瞬時値 | 次回韻律決定への入力 |

#### 5.2.2 スライディングウィンドウによる中央値算出

発話開始時の心拍数は、単一時点の瞬時値ではなく、時間窓内のサンプルの中央値として算出する。この設計の根拠は以下の通りである：

1. **ノイズ耐性**：PPGセンサは体動によるアーチファクトの影響を受けやすい。中央値は外れ値に頑健であり、一時的なノイズの影響を軽減できる。

2. **サンプリング不確実性の緩和**：心拍は約1Hzで取得されるため、特定時刻の「瞬時心拍」は直近1秒以内に検出された拍動に基づく。時間窓を設けることで、この離散性の影響を軽減する。

3. **生理的意味**：心拍数は呼吸等により数秒周期で変動する（呼吸性洞性不整脈; RSA）。5サンプル程度の中央値は、この短周期変動を平滑化し、より安定した生理状態の指標となる。

**時間窓の設計：**

```
時間軸:     -2秒    -1秒    0秒      +1秒    +2秒
                           (発話開始)
             ↓       ↓       ↓        ↓       ↓
心拍取得:   [HR₋₂]  [HR₋₁]  [HR₀]   [HR₊₁]  [HR₊₂]
                           ↓
                    中央値算出 (5サンプル)
```

**実装：**

```python
def get_buffered_hr(self, target_time, window_seconds=2.0):
    """
    指定時刻を中心とした時間窓から心拍数の中央値を算出

    発話開始時刻の前2秒＋開始時点＋後2秒で計5サンプル程度を取得し、
    中央値を算出することでノイズの影響を軽減する。

    Args:
        target_time: 中心時刻（発話開始時刻）
        window_seconds: 前後の時間幅（秒）、デフォルト2秒

    Returns:
        int: 心拍数の中央値（BPM）、データ不足時はNone
    """
    window_start = target_time - timedelta(seconds=window_seconds)
    window_end = target_time + timedelta(seconds=window_seconds)

    hr_values = [
        entry['hr'] for entry in self.hr_buffer
        if window_start <= entry['timestamp'] <= window_end
    ]

    if len(hr_values) >= MIN_SAMPLES_FOR_MEDIAN:  # デフォルト: 5
        return int(statistics.median(hr_values))
    return None
```

## 6. 心拍フィードバック制御機構

### 6.1 制御理論の背景

#### 6.1.1 閉ループ制御の必要性

音声韻律による心拍誘導は、以下の特性を持つ複雑な制御対象である：

1. **遅延（むだ時間）**：韻律変化から心拍応答までに数十秒の遅延がある
2. **非線形性**：心拍応答は韻律変化量に対して線形ではない可能性がある
3. **個人差**：心拍の韻律感受性には大きな個人差がある
4. **時変性**：同一被験者でも疲労・覚醒度により応答特性が変化する
5. **外乱**：会話内容、感情喚起等の心拍への外乱が存在する

これらの特性に対応するため、本システムでは閉ループ制御（フィードバック制御）を採用した。閉ループ制御は、制御対象の応答を計測し、目標値との偏差に基づいて操作量を調整することで、モデル誤差や外乱の影響を補償できる。

#### 6.1.2 制御ブロック図

```
                    ┌─────────────────────────────────────────────────────┐
                    │                  閉ループ制御系                      │
                    └─────────────────────────────────────────────────────┘

     r(t)         e(t)        u(t)                    y(t)
  目標心拍 ──(+)──►[制御器 C]──►[ 抑揚 ]──►[ 人体 G ]──┬──► 現在心拍
     ↑       │                                        │
     │       │        ┌─────────────────┐             │
     │       └◄───────│   センサ H      │◄────────────┘
     │                │ (Polar Verity)  │
     │                └─────────────────┘
     │
     └─ 基準心拍 × 1.10 (相対目標)


  記号の定義:
    r(t): 目標心拍数 (HR_target)
    e(t): 偏差 = r(t) - y(t)
    u(t): 抑揚パラメータ (intonationScale)
    y(t): 現在心拍数 (HR_current)
    C:    制御器 (PID / MRAC / Gain-Scheduled / Robust)
    G:    制御対象 (人体の心拍応答特性)
    H:    センサ (心拍計測系)
```

### 6.2 制御モードの概要

本システムは5種類の制御モードを実装している：

| モード | 名称 | 制御方式 | 特徴 | 用途 |
|--------|------|---------|------|------|
| Fixed | 固定値 | 開ループ | 手動設定値を維持 | 対照条件 |
| Sin | 正弦波 | 開ループ | 心拍非依存で周期変化 | 韻律効果の検証 |
| HRF | 直接調整 | 閉ループ（比例） | 心拍偏差×感度係数 | 単純フィードバック |
| HRF2-PID | PID制御 | 閉ループ（PID） | 古典制御 | 基本的な追従制御 |
| HRF2-Adaptive | 適応制御 | 閉ループ（MRAC） | ゲイン自動調整 | 個人差への適応 |
| HRF2-GS | ゲインスケジューリング | 閉ループ（切替PID） | 領域別ゲイン | 大偏差時の高速応答 |
| HRF2-Robust | ロバスト制御 | 閉ループ（MEC） | モデル誤差補償 | 頑健性確保 |

### 6.3 固定値モード（Fixed）

固定値モードは、心拍数に関係なく韻律パラメータを手動設定値に固定するモードである。制御効果を評価するための**対照条件（コントロール条件）**として使用する。

```python
# 固定値モードの動作
intonation = prosody_settings.get_parameter("intonation")  # 手動設定値
```

### 6.4 正弦波モード（Sin）

正弦波モードは、心拍数に依存せず、韻律パラメータを周期的に変化させるモードである。**韻律変化自体が心拍に与える影響**を評価するための条件として使用する。

**シーケンス設計：**

三角波形状の抑揚シーケンス（40ステップで1周期）を生成する：

```
抑揚値
  2.0 ├───────────╱╲──────────────────────────
      │          ╱  ╲
  1.0 ├─────────╱    ╲──────────────────────
      │        ╱      ╲
  0.0 ├───────╱        ╲─────────────╱──────
      └────────────────────────────────────► ステップ
        0    10    20    30    40 (=0)
             上昇   下降    回復
```

**シーケンス生成アルゴリズム：**

```python
def _generate_sinusoidal_sequence():
    """三角波形状の抑揚シーケンスを生成"""
    sequence = []

    # Phase 1: 上昇相（1.0 → 2.0, 11ステップ）
    for i in range(11):
        sequence.append(round(1.0 + i * 0.1, 1))

    # Phase 2: 下降相（1.9 → 0.0, 20ステップ）
    for i in range(20):
        sequence.append(round(1.9 - i * 0.1, 1))

    # Phase 3: 回復相（0.1 → 0.9, 9ステップ）
    for i in range(9):
        sequence.append(round(0.1 + i * 0.1, 1))

    return sequence  # 合計40ステップ
```

各音声合成時に1ステップずつ進行し、40発話で1周期を完了する。

### 6.5 直接調整モード（HRF）

直接調整モードは、基準心拍数からの偏差に感度係数を乗じて韻律パラメータを算出する**比例制御**である。

#### 6.5.1 基本計算式

$$
p = p_0 + k \cdot (HR_{after} - HR_{ref})
$$

ここで：
- $p$：適用される韻律パラメータ値
- $p_0$：基本値（デフォルト値）
- $k$：感度係数
- $HR_{after}$：前回音声再生後の心拍数（BPM）
- $HR_{ref}$：基準心拍数（BPM）

#### 6.5.2 パラメータ設定

| 韻律パラメータ | 基本値 $p_0$ | 感度係数 $k$ | 制御範囲 | 1BPM偏差あたりの変化 |
|--------------|-------------|-------------|---------|---------------------|
| intonation | 1.0 | 0.10 | [0.0, 2.0] | ±10% |
| pitch | 0.0 | 0.002 | [-0.15, 0.15] | ±0.2% |
| speed | 1.0 | 0.003 | [0.5, 2.0] | ±0.3% |
| energy | 1.0 | 0.005 | [0.0, 2.0] | ±0.5% |
| pause_duration | 1.0 | 0.003 | [0.0, 2.0] | ±0.3% |

#### 6.5.3 計算例

基準心拍数 $HR_{ref} = 70$ BPM、前回再生後心拍数 $HR_{after} = 85$ BPMの場合：

$$
\text{intonation} = 1.0 + 0.1 \times (85 - 70) = 1.0 + 1.5 = 2.5
$$

制御範囲[0.0, 2.0]に制限されるため、実際に適用される値は**2.0**となる。

#### 6.5.4 制御の意図

この制御則は、**心拍上昇時に抑揚を強める**設計となっている。これは直感に反するように思えるが、以下の仮説に基づく：

- 心拍が高い状態（興奮状態）の被験者には、抑揚の強い音声がマッチする
- 音声と生理状態の一致（同期）が心理的快適さをもたらす

ただし、心拍を**下げる**ことが目的の場合は、感度係数を負にする必要がある。

### 6.6 HRF2制御モード

HRF2は、**目標心拍数への追従**を目的とした閉ループ制御モードであり、4種類の制御アルゴリズムを実装している。

#### 6.6.1 PID制御（ControlMode.PID）

PID（Proportional-Integral-Derivative）制御は、産業界で最も広く使用される古典的制御手法である。

**制御則：**

$$
u(t) = u_0 + K_p e(t) + K_i \int_0^t e(\tau) d\tau + K_d \frac{de(t)}{dt}
$$

ここで：
- $u(t)$：抑揚パラメータ（操作量）
- $u_0 = 1.0$：基準抑揚値
- $e(t) = HR_{target} - HR_{current}$：偏差
- $K_p, K_i, K_d$：比例、積分、微分ゲイン

**各項の役割：**

| 項 | 役割 | 特性 |
|---|------|------|
| 比例（P） | 現在の偏差に応答 | 即応性、定常偏差あり |
| 積分（I） | 累積偏差を補償 | 定常偏差除去、応答遅れ |
| 微分（D） | 偏差変化率を予測 | 応答速度向上、ノイズ感度 |

**実装上の工夫：**

1. **デッドバンド処理**

   目標心拍付近での過剰な制御動作（チャタリング）を防止するため、偏差が閾値以下の場合は偏差をゼロとして扱う：

   $$
   e_{eff}(t) = \begin{cases}
   e(t) & \text{if } |e(t)| > \text{deadband} \\
   0 & \text{otherwise}
   \end{cases}
   $$

   デッドバンド幅：3.0 BPM

2. **アンチワインドアップ**

   操作量が飽和している状態で積分が蓄積し続けると、飽和解除後に過大な制御動作が発生する（ワインドアップ現象）。これを防止するため、積分値を制限する：

   $$
   \int e \, dt \in [-I_{max}, I_{max}]
   $$

   積分上限：$I_{max} = 20.0$

3. **離散化**

   連続時間PIDを離散時間に変換する。微分項は後退差分法で近似：

   $$
   \frac{de}{dt} \approx \frac{e[k] - e[k-1]}{\Delta t}
   $$

   積分項は台形法または矩形法で累積：

   $$
   \int e \, dt \approx \sum_{i=0}^{k} e[i] \cdot \Delta t
   $$

**デフォルトパラメータ：**

| パラメータ | 値 | 選定根拠 |
|-----------|-----|---------|
| $K_p$ | 0.02 | 10BPM偏差で抑揚0.2変化 |
| $K_i$ | 0.005 | 長期偏差の緩やかな補償 |
| $K_d$ | 0.01 | ノイズ増幅を抑えつつ応答改善 |
| デッドバンド | 3.0 BPM | 心拍の自然変動幅 |
| 積分上限 | 20.0 | 抑揚2.0飽和までの余裕 |

#### 6.6.2 適応制御（ControlMode.ADAPTIVE）

適応制御は、制御対象のパラメータが未知または時変の場合に、制御器パラメータを実時間で調整する手法である。本システムでは、**モデル規範型適応制御（MRAC: Model Reference Adaptive Control）**を実装した。

**適応制御の必要性：**

心拍の韻律感受性には大きな個人差があり、固定ゲインのPID制御では全被験者に対して最適な制御性能を達成できない。MRACは、被験者の応答特性を実時間で学習し、ゲインを自動調整する。

**制御構造：**

```
     r(t)                              y(t)
  目標心拍 ───┬──►[参照モデル Gm]──► y_m(t)
              │                         │
              │         e_track = y_m - y
              │                         │
              └──►[適応制御器]────────►[人体 G]──► y(t)
                       ↑                    │
                       │                    │
                       └────[適応則]◄───────┘
```

**参照モデル：**

被験者の心拍応答が「理想的に」追従すべき軌道を定義する。一次遅れ系を採用：

$$
G_m(s) = \frac{1}{\tau s + 1}
$$

離散化形式：

$$
r[k+1] = r[k] + \frac{\Delta t}{\tau} (HR_{target} - r[k])
$$

時定数 $\tau = 30$ 秒は、心拍数の生理的応答遅れを考慮して設定した。

**適応則（MIT則）：**

MIT則（Massachusetts Institute of Technology rule）は、最も基本的な適応則である。追従誤差の二乗を最小化するよう、適応パラメータを勾配降下法で更新する：

$$
\theta[k+1] = \lambda \cdot \theta[k] + \gamma \cdot \frac{e_{track} \cdot u_{sens}}{1 + \alpha \cdot u_{sens}^2}
$$

ここで：
- $\theta$：適応ゲイン
- $\lambda = 0.995$：忘却係数（古い情報の重みを減衰）
- $\gamma = 0.001$：適応速度（学習率）
- $\alpha = 0.01$：正規化ゲイン（発散防止）
- $e_{track} = y_m - y$：追従誤差
- $u_{sens}$：感度信号（前回操作量）

**制御出力：**

$$
u(t) = u_0 + \theta \cdot e_{control}
$$

ここで $e_{control} = HR_{target} - HR_{current}$（デッドゾーン処理後）。

**安定性確保：**

- 適応ゲインの制限：$\theta \in [0.005, 0.1]$
- 正規化による発散防止
- 忘却係数による古い学習の減衰

#### 6.6.3 ゲインスケジューリング制御（ControlMode.GAIN_SCHEDULED）

ゲインスケジューリングは、動作点に応じて制御器パラメータを切り替える手法である。本システムでは、**偏差の大きさ**に応じてPIDゲインを3段階に切り替える。

**設計思想：**

- **大偏差時**：高ゲインで積極的に追従（収束速度優先）
- **中偏差時**：標準ゲインでバランスの取れた制御
- **小偏差時**：低ゲインで微調整（安定性優先）

**ゲイン領域の定義：**

| 領域 | 条件 | $K_p$ | $K_i$ | $K_d$ | 制御特性 |
|-----|------|-------|-------|-------|---------|
| High | $|e| \geq 15$ BPM | 0.04 | 0.008 | 0.015 | 積極的追従 |
| Medium | $7 \leq |e| < 15$ BPM | 0.02 | 0.005 | 0.01 | バランス |
| Low | $|e| < 7$ BPM | 0.01 | 0.002 | 0.005 | 微調整 |

**ゲイン平滑化：**

急激なゲイン切り替えはチャタリングを引き起こす。指数移動平均による平滑化を適用：

$$
K[k+1] = K[k] + \alpha_s (K_{target} - K[k])
$$

平滑化係数 $\alpha_s = 0.3$。

#### 6.6.4 ロバスト制御（ControlMode.ROBUST）

ロバスト制御は、モデル誤差や外乱に対して頑健な制御性能を維持する手法である。本システムでは、**モデル誤差補償器（MEC: Model Error Compensator）**を用いた2自由度制御系を実装した。

**設計動機：**

心拍の韻律応答には大きな個人差と時変性がある。名目モデルに基づく制御器だけでは、モデル誤差により性能が劣化する。MECは、名目モデルと実応答の差を検出し、制御入力に補正を加える。

**制御構造：**

```
                              ┌────────────────────────────────────────┐
                              │              ロバスト制御系             │
                              └────────────────────────────────────────┘

     r(t)         e(t)                u(t)                    y(t)
  目標心拍 ──(+)──►[PI制御器 K₀]──(+)──►[ 抑揚 ]──►[ 人体 G ]──┬──► 心拍
     ↑       │              ↑                                │
     │       │              │ u_mec                          │
     │       │              │                                │
     │       │         [MEC補償器]◄────┐                     │
     │       │              ↑          │                     │
     │       │              │ ε        │                     │
     │       │              │          │                     │
     │       │         (─)◄─┤          │                     │
     │       │          │   │          │                     │
     │       │          ▼   │ ŷ        │                     │
     │       │   [名目モデル Ĝ]◄────────┤                     │
     │       │                          │                     │
     │       └◄─────────────────────────┴─────────────────────┘
     │
     └─ 基準心拍 × 1.10
```

**基本PI制御器 $K_0$：**

$$
u_0(t) = u_{base} + K_p e(t) + K_i \int e \, dt
$$

パラメータ：$K_p = 0.02$, $K_i = 0.003$, $u_{base} = 1.0$

**名目モデル $\hat{G}$：**

一次遅れ系にむだ時間を加えたモデル：

$$
\hat{G}(s) = \frac{K}{1 + \tau s} e^{-Ls}
$$

パラメータ：
- $K = 5.0$：定常ゲイン（抑揚1.0変化 → HR 5BPM変化）
- $\tau = 30$ 秒：時定数
- $L = 5$ 秒：むだ時間

離散化実装（むだ時間は入力バッファで実現）：

$$
\hat{y}[k+1] = \hat{y}[k] + \frac{\Delta t}{\tau + \Delta t} \left( K \cdot (u_{delayed} - 1.0) + HR_{baseline} - \hat{y}[k] \right)
$$

**MEC補償器 $C_\varepsilon$：**

モデル誤差 $\varepsilon = y - \hat{y}$ を低域通過フィルタを通して補償入力に変換：

$$
C_\varepsilon(s) = \frac{k_{mec}}{1 + s/\omega_c}
$$

離散化：

$$
\varepsilon_{filtered}[k+1] = \varepsilon_{filtered}[k] + \alpha_{mec} (k_{mec} \cdot \varepsilon - \varepsilon_{filtered}[k])
$$

補償入力：

$$
u_{mec} = -\varepsilon_{filtered}
$$

パラメータ：
- $k_{mec} = 0.3$：MEC利得
- $\omega_c = 0.05$ rad/s：カットオフ周波数

**スルーレート制限：**

急激な抑揚変化は不自然な音声となる。1ステップあたりの変化量を制限：

$$
|u[k] - u[k-1]| \leq 0.15
$$

**計測ノイズフィルタ：**

心拍計測値のノイズを抑制する一次ローパスフィルタ：

$$
HR_{filtered}[k+1] = HR_{filtered}[k] + \frac{\Delta t}{\tau_f + \Delta t} (HR_{raw} - HR_{filtered}[k])
$$

時定数 $\tau_f = 2.0$ 秒。

## 7. 目標心拍数の設定方法

### 7.1 基準心拍数の測定

#### 7.1.1 測定プロトコル

実験開始前に、被験者の安静時心拍数をベースライン測定により取得する。

**手順：**

1. 被験者に椅子座位で安静を維持するよう指示
2. 心拍センサ装着後、指定時間（デフォルト30秒）の心拍数を連続記録
3. 取得したサンプルから**中央値**を算出し、基準心拍数（$HR_{ref}$）として設定

**中央値採用の根拠：**

- 体動等によるアーチファクト（外れ値）の影響を軽減
- 正規分布を仮定しない頑健な代表値
- 呼吸性洞性不整脈による短期変動を平滑化

**実装：**

```python
def stop_baseline_measurement(self):
    """ベースライン測定を終了し、中央値を基準心拍数として設定"""
    if len(self.baseline_samples) >= MIN_SAMPLES_FOR_MEDIAN:
        median_hr = int(statistics.median(self.baseline_samples))
        self.set_reference_hr(median_hr)
        return median_hr
    return None
```

### 7.2 目標心拍数の設定根拠

#### 7.2.1 相対目標設定の採用理由

先行研究（第1章参照）に基づき、固定値ではなく**基準心拍数からの相対変化**で目標を設定する：

$$
HR_{target} = HR_{ref} \times (1 + \alpha)
$$

**相対目標の利点：**

1. **個人差の吸収**：安静時心拍数は60-90 BPMと個人差が大きい
2. **生理的妥当性**：相対変化は自律神経活動の変化量を反映
3. **制御安定性**：固定目標への過度な追従は不安定化のリスク

**先行研究からの知見：**

| 研究 | 介入方法 | 目標設定 |
|------|---------|---------|
| Costa et al. (2016) | 心拍表示オフセット | 実測の70%/130% |
| Azevedo et al. (2017) | 振動刺激 | 現在値の-3%〜-5% |
| VNS研究 | 迷走神経刺激 | 医師が定義 + 安全制約 |

#### 7.2.2 目標値の設定例

本研究では、会話による覚醒水準の適度な向上を目的とし、**基準心拍数の+10%**を目標値として設定した：

$$
HR_{target} = HR_{ref} \times 1.10
$$

**具体例：**

| 基準心拍数 | 目標心拍数 | 偏差 |
|-----------|-----------|------|
| 60 BPM | 66 BPM | +6 BPM |
| 70 BPM | 77 BPM | +7 BPM |
| 80 BPM | 88 BPM | +8 BPM |

**+10%設定の根拠と限界：**

ヤーキーズ・ドットソンの法則（Yerkes-Dodson law）によれば、パフォーマンスは覚醒水準の逆U字関数であり、中程度の覚醒で最大となる。+10%という設定は、この最適覚醒理論を参考にしている。

ただし、以下の点に留意が必要である：

1. **エビデンスの限界**：音声韻律による心拍誘導効果に関する先行研究は限定的
2. **タスク依存性**：最適覚醒水準はタスク複雑性に依存
3. **個人差**：覚醒と心拍の関係には個人差がある

したがって、+10%は**探索的な設定**として位置づけ、実験を通じた検証が必要である。

#### 7.2.3 安全制約

目標心拍数は以下の範囲に制限される：

$$
40 \leq HR_{target} \leq 180 \text{ (BPM)}
$$

この範囲は、以下の生理学的考慮に基づく：

- **下限40 BPM**：徐脈による症状（めまい、失神）を防止
- **上限180 BPM**：過度の頻脈による心臓負荷を防止

また、デッドバンド（±2〜3 BPM）の設定により、目標値付近での過剰な制御動作を抑制している。

## 9. ECG解析機能

### 9.1 QRS検出アルゴリズム

Polar H10から取得したECGデータからR波を検出し、RR間隔（RRI: R-R Interval）を算出する。

#### 9.1.1 Pan-Tompkinsアルゴリズム

本システムでは、Pan & Tompkins (1985)のアルゴリズムを参考に実装した。

**処理パイプライン：**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          QRS検出パイプライン                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  [ECG生信号] ──► [バンドパスフィルタ] ──► [微分] ──► [二乗] ──► [移動積分]   │
│       ↓                0.5-50 Hz                                            │
│                                                                    ↓        │
│                                                            [ピーク検出]      │
│                                                                    ↓        │
│                                                              [RRI算出]       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**各段階の詳細：**

1. **バンドパスフィルタリング**
   - 通過帯域：0.5 Hz - 50 Hz
   - 目的：ベースラインワンダー（低周波ドリフト）と高周波ノイズ（筋電図、電源干渉）の除去
   - 実装：Butterworth IIRフィルタ

2. **微分処理**

   QRS複合体の急峻な傾斜を強調：

   $$
   y[n] = x[n] - x[n-1]
   $$

3. **二乗処理**

   全ての値を正にし、大きな変化を強調：

   $$
   z[n] = y[n]^2
   $$

4. **移動積分**

   QRS複合体の幅に対応した窓で平滑化：

   $$
   w[n] = \frac{1}{N} \sum_{i=0}^{N-1} z[n-i]
   $$

   窓幅：150 ms（130Hz × 0.15 = 約20サンプル）

5. **ピーク検出**
   - 閾値：積分信号平均値の40%
   - 最小ピーク間隔：300 ms（生理学的に妥当なRR間隔下限、200 BPM相当）

### 9.2 心拍変動（HRV）指標

検出されたRR間隔から以下のHRV指標を算出可能である。

#### 9.2.1 時間領域指標

| 指標 | 定義 | 計算式 | 意味 |
|------|------|-------|------|
| SDNN | RR間隔の標準偏差 | $\sqrt{\frac{1}{N-1}\sum_{i=1}^{N}(RR_i - \overline{RR})^2}$ | 全体的な心拍変動性 |
| RMSSD | 隣接RR間隔差の二乗平均平方根 | $\sqrt{\frac{1}{N-1}\sum_{i=1}^{N-1}(RR_{i+1} - RR_i)^2}$ | 副交感神経活動 |
| pNN50 | 50ms以上異なる隣接RR間隔の割合 | $\frac{\#\{|RR_{i+1} - RR_i| > 50\text{ms}\}}{N-1} \times 100$ | 副交感神経活動 |

#### 9.2.2 周波数領域指標

| 指標 | 周波数帯域 | 意味 | 生理学的背景 |
|------|-----------|------|-------------|
| VLF | 0.003 - 0.04 Hz | 超低周波成分 | 体温調節、ホルモン変動 |
| LF | 0.04 - 0.15 Hz | 低周波成分 | 交感・副交感神経活動 |
| HF | 0.15 - 0.40 Hz | 高周波成分 | 副交感神経（迷走神経）活動 |
| LF/HF比 | - | 自律神経バランス | 交感/副交感のバランス指標 |

**周波数解析手法：**

- Welch法によるパワースペクトル密度推定
- ハニング窓、オーバーラップ50%
- RR間隔の不等間隔性に対応するため、スプライン補間で等間隔リサンプリング

## 10. スレッド安全性とエラーハンドリング

### 10.1 マルチスレッド構成

本システムは以下の複数スレッドが並行動作する：

| スレッド | 役割 | 主要処理 |
|---------|------|---------|
| メインスレッド | GUI、ユーザーインタラクション | Tkinterイベントループ |
| BLE通信スレッド | 心拍センサ通信 | asyncio + bleak |
| 音声処理スレッド | 録音、認識、合成 | sounddevice + whisper + VOICEVOX |
| ログ記録スレッド | ファイル書き込み | CSV出力 |

### 10.2 排他制御機構

共有リソースへのアクセスには適切な排他制御を実装した：

| 共有リソース | ロック機構 | 保護対象 |
|-------------|-----------|---------|
| 心拍数データ | `threading.Lock` (hr_lock) | current_hr, hr_buffer |
| TTS処理状態 | `threading.Lock` (tts_lock) | 音声合成・再生の排他 |
| ログキュー | `queue.Queue` | スレッドセーフなキュー |

**実装例：**

```python
class HeartRateMonitor:
    def __init__(self):
        self.hr_lock = threading.Lock()
        self.current_hr = 0
        self.hr_buffer = []

    def get_current_hr(self) -> int:
        """心拍数の取得（スレッドセーフ）"""
        with self.hr_lock:
            return self.current_hr

    def hr_notification_handler(self, sender, data):
        """BLE通知ハンドラ（スレッドセーフな更新）"""
        hr_value = self._parse_hr_data(data)
        with self.hr_lock:
            self.current_hr = hr_value
            self.hr_buffer.append({
                'timestamp': datetime.now(),
                'hr': hr_value
            })
```

### 10.3 BLE接続エラー処理

#### 10.3.1 Linux BlueZ特有の問題

Linux環境（BlueZスタック）では、BLE接続時に「org.bluez.Error.InProgress」エラーが発生することがある。これは、前回の接続試行がまだ完了していない状態で新たな接続を試みた場合に発生する。

**対策：**

1. **順次接続**：複数デバイス（Verity Sense, H10）を同時ではなく順次接続
2. **強制切断**：bluetoothctlコマンドで既存接続をクリーンアップ
3. **リトライ機構**：最大3回の接続試行

```python
async def _bluez_disconnect_device(self, address: str) -> None:
    """Linux BlueZ: bluetoothctlでデバイスを強制切断"""
    # 既存接続の切断
    subprocess.run(
        ["bluetoothctl", "disconnect", address],
        capture_output=True, timeout=5
    )
    await asyncio.sleep(1.0)

    # デバイス情報の削除（ペアリング解除）
    subprocess.run(
        ["bluetoothctl", "remove", address],
        capture_output=True, timeout=5
    )
```

## 11. システムの特徴と限界

### 11.1 特徴

1. **リアルタイム閉ループ制御**
   - 心拍計測から韻律調整までを低遅延で実行
   - 制御理論に基づく4種類のアルゴリズム実装

2. **無意識的介入（Mindless Intervention）**
   - 被験者の意識的努力を必要としない
   - 自然な会話を通じた生理状態への働きかけ

3. **研究プラットフォームとしての柔軟性**
   - 複数の制御モードを比較可能
   - 包括的なデータログ機能
   - 設定ファイルによるパラメータカスタマイズ

4. **クロスプラットフォーム対応**
   - macOS（Apple Silicon）、Ubuntu Linux
   - GPU自動検出と最適化

### 11.2 限界

1. **心拍応答の遅延**
   - 音声韻律変化から心拍応答までに数十秒の遅延
   - 閉ループ制御の帯域幅が制限される
   - リアルタイムの精密な心拍制御は困難

2. **個人差**
   - 心拍の韻律感受性には大きな個人差
   - 固定パラメータでは全被験者に最適な制御が困難
   - 適応制御の効果は検証が必要

3. **外乱の影響**
   - 会話内容、感情喚起による心拍変動
   - 環境温度、姿勢変化、身体活動
   - 制御効果の評価が困難

4. **エビデンスの限界**
   - 音声韻律による心拍誘導の先行研究は限定的
   - 最適な目標心拍数設定（+10%等）の根拠は探索的
   - 本研究を通じた検証が必要

5. **生態学的妥当性**
   - 実験室環境は日常会話と異なる
   - 対話相手がAI（非人間）
   - 知見の一般化には慎重さが必要

6. **技術的制約**
   - PPGセンサは体動アーチファクトに弱い
   - BLE通信の不安定性（特にLinux環境）
   - LLM応答の予測不可能性
